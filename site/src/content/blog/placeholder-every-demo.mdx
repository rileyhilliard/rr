## Start with one run

This placeholder exercises the article engine before the how-to guides arrive. Start with a small command and a host you can already reach over SSH. Keeping that first run short makes the setup easier to inspect. The monitor below replays an existing recording, so its output comes from a real run rather than an invented terminal session.

<MonitorDemo caption="A recorded parallel test run and its host monitor." />

The [configuration reference](/docs/configuration/) describes the settings used by real projects. Check the host names and working directories before sending a larger suite. A successful connection is only the first step: the remote machine also needs your project's toolchain and dependencies.

> [!NOTE]
> This is a temporary article for checking the blog components. The recordings remain useful without JavaScript.

```yaml title=".rr.yaml"
hosts: [mini]
local_fallback: false
```

## Share the machines

Several agents can request a run at once. A host lock keeps their test processes from sharing the same machine. When the pool is busy, waiting happens on the requesting laptop. The queue demonstration lets you free one host and watch the waiting run take its place.

<QueueDemo caption="Free a host to see the next waiting run start." />
